# Geo-based Top Charts Feature

## Краткое описание

Функциональность "топ треков в радиусе" позволяет собирать и отдавать популярные треки в определённом географическом радиусе вокруг заданной точки (широта, долгота).

## Основные компоненты

### 1. GeoTopStore
- **Файл**: `internal/store/geohash_top_store.go`
- **Функции**:
  - Хранение агрегатов прослушиваний по геохешам
  - Инкремент счётчиков при поступлении событий с координатами
  - Получение топ-N треков в радиусе
  - Snapshot/restore для MinIO backup

### 2. Consumer Integration
- **Файл**: `internal/consumer/consumer.go`
- Обрабатывает события прослушивания с опциональными полями `lat` и `lon`
- При наличии координат вычисляет geohash и обновляет агрегаты

### 3. HTTP API
- **Эндпоинт**: `GET /charts/top/nearby`
- **Параметры**:
  - `lat` (обязательный): широта
  - `lon` (обязательный): долгота
  - `radius_m` (опционально, по умолчанию 1000): радиус поиска в метрах
  - `limit` (опционально, по умолчанию 20): количество результатов

### 4. LocalTopGenerator
- **Файл**: `internal/engine/generators/local_top.go`
- Генератор кандидатов для рекомендаций на основе геолокации
- Использует метод `GenerateWithLocation(lat, lon, radiusM)` для получения топа в радиусе

## Конфигурация

Все настройки задаются через переменные окружения:

```bash
# Включить функциональность
ENABLE_GEO_TOP=true

# Точность геохеша (1-10, чем выше - тем точнее, но больше памяти)
# 6 ≈ 1.2 км, 7 ≈ 153 м, 8 ≈ 38 м
GEOHASH_PRECISION=6

# TTL кеша результатов запросов
GEO_TOP_CACHE_TTL=60s

# Максимальное количество треков на один геохеш
GEO_TOP_MAX_PER_GEO=1000

# Радиус поиска по умолчанию (метры)
GEO_TOP_DEFAULT_RADIUS_M=1000
```

## Примеры использования

### 1. Отправка события прослушивания с координатами

```bash
curl -X POST http://localhost:8080/ingest/listening \
  -H "Content-Type: application/json" \
  -d '{
    "event_type": "track_listened",
    "user_id": "user1",
    "track_id": "track1",
    "listened_seconds": 180,
    "ts": 1734134400,
    "lat": 59.9311,
    "lon": 30.3609
  }'
```

### 2. Получение топа треков в радиусе

```bash
# Топ-20 треков в радиусе 2 км от Санкт-Петербурга
curl "http://localhost:8080/charts/top/nearby?lat=59.9311&lon=30.3609&radius_m=2000&limit=20"
```

## Архитектурные решения

### Геохеш индексация
- Использует библиотеку `github.com/mmcloughlin/geohash`
- Пространственная индексация через geohash сетку
- Precision автоматически подбирается на основе радиуса

### Кеширование
- Результаты запросов кешируются с TTL
- Инвалидация кеша при обновлении агрегатов
- Ключ кеша: `sorted_geohashes + limit`

### Персистентность
- Агрегаты сохраняются в MinIO вместе с остальными store
- Snapshot/restore поддерживается из коробки
- JSON сериализация: `map[geohash]map[trackID]count`

### Производительность
- Потокобезопасные операции (sync.RWMutex)
- Кеширование частых запросов
- Ограничение количества треков на геохеш (GEO_TOP_MAX_PER_GEO)

## Производственное развёртывание

1. **Staging**:
   - Включить флаг `ENABLE_GEO_TOP=true`
   - Прогнать интеграционные тесты
   - Проверить MinIO snapshot/restore

2. **Production**:
   - Включать постепенно (canary deployment)
   - Мониторить использование памяти
   - Настроить `GEO_TOP_MAX_PER_GEO` в зависимости от нагрузки

3. **Опциональный backfill**:
   - Если есть исторические данные с координатами
   - Создать отдельный job для заполнения агрегатов

## Ограничения и рекомендации

- **Память**: Контролируйте GEO_TOP_MAX_PER_GEO при больших нагрузках
- **Приватность**: Координаты агрегированы по геохешам, индивидуальные данные не хранятся
- **Точность**: Precision 6-7 оптимален для большинства случаев (город/район)
- **Производительность**: TTL кеша снижает нагрузку при частых запросах
